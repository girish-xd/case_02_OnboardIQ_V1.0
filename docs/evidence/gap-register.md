# OnboardIQ — Gap & Ambiguity Register

This register documents all technical assumptions, architectural choices, and external service handling reconciled against the original case study specification (`case_02_OnboardIQ_V1.0.docx`).

| Item ID | Topic | Source Specification | Resolved Implementation / Safe Behaviour | Impact & Verification |
| :--- | :--- | :--- | :--- | :--- |
| **GAP-01** | **Evaluation Ground Truth Labels** | Case study Section 9 explicitly notes that `case_02_EVALUATOR_ONLY_document_truth_eval_V1.0.csv` and `case_02_EVALUATOR_ONLY_eval_answer_key_V1.0.csv` are evaluator-only files and withheld from participants. | We evaluate field extraction accuracy against `case_02_document_truth_sample_V1.0.csv` (178 documents) where ground truth is provided. For the 100 evaluation applications, we generate `/output/decisions_output.csv` deterministically via the mock and AI extraction pipelines without fabricating truth labels. | Zero fabrication; compliant with case study principles. |
| **GAP-02** | **Document Storage & Private Access** | Case study requires documents to be stored outside DB or with hash, never public, access strictly authorized and audited. Prompt allows Cloudinary only if private/authenticated. | Implemented a pluggable Document Storage Adapter: `LocalSecureStorageAdapter` (stores files in private storage directory hashed by SHA-256, strictly served via authenticated Express route `/api/v1/documents/:doc_id/file`) with optional `CloudinaryStorageAdapter` when signed URLs are configured. | High security; no public URL leaks; 100% offline testable. |
| **GAP-03** | **Database Persistence & Testing** | MongoDB Atlas is the specified cloud database target; local runs need zero-friction, isolated test environments. | Implemented Mongoose persistence with flexible connection string (`MONGODB_URI`). If `MONGODB_URI` is not set or in test mode, the server can spin up an embedded in-memory MongoDB instance (`mongodb-memory-server`) or connect to local MongoDB. | Ensures reproducible local test runs, CI execution, and Atlas production readiness. |
| **GAP-04** | **Groq LLM Integration for Reviewer Summary** | Case study AI-5 allows optional LLM reviewer summary (max 80 words, labelled "AI-generated", no decision recommendations). | Implemented `GroqReviewerSummaryService` with strict prompt guardrails, redaction of full PII, and an automated deterministic fallback when `GROQ_API_KEY` is unset or fails. | System never blocks on external AI service; zero risk to rule decisions. |
| **GAP-05** | **Status vs Decision Terminology Alignment** | Case study uses business decisions (`APPROVE`, `REVIEW`, `REJECT`) alongside workflow statuses (`SUBMITTED`, `EXTRACTING`, `AUTO_APPROVED`, `IN_REVIEW`, `RESUBMISSION_REQUESTED`, `PENDING_CHECKER`, `APPROVED`, `REJECTED`, `AUTO_REJECTED`, `CLOSED_EXPIRED`). | Strict mapping enforced: <br>- `APPROVE` + LOW/MEDIUM risk -> `AUTO_APPROVED`<br>- `APPROVE` + HIGH risk -> `PENDING_CHECKER`<br>- `REVIEW` -> `IN_REVIEW`<br>- `REJECT` -> `AUTO_REJECTED`<br>- Officer recommendation moves `IN_REVIEW` -> `PENDING_CHECKER` or `RESUBMISSION_REQUESTED`<br>- Checker decision moves `PENDING_CHECKER` -> `APPROVED` or `REJECTED` or sends back to `IN_REVIEW`. | Fully reconciles Section 6.1 with Section 6.1.1 lifecycle. |
| **GAP-06** | **Core-Banking Mock Service** | Case study specifies mock core-banking API that returns `customer_id` and `account_number` upon approval. | Implemented idempotent synthetic banking adapter generating predictable customer IDs (`CUST-DDB-XXXXXX`) and account numbers (`1001XXXXXXXX`), invoked only on transitions to `AUTO_APPROVED` or `APPROVED`. | Idempotent; duplicate approval calls return the existing account. |
| **GAP-07** | **Password / Auth for Demo Users** | Case study outlines 4 roles (Applicant, KYC Officer/Maker, Compliance Officer/Checker, Admin) with seed data. | Pre-seeded accounts provided with secure bcrypt-hashed credentials, standard demo logins documented, plus self-registration for Applicants. | Easy demo experience while maintaining bcrypt and JWT cookie security. |
